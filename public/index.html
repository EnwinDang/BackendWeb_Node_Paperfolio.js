Price Alerts API

A database-driven REST API for tracking cryptocurrency assets and letting people request an alert when an asset reaches a target price. Built with Node.js, Express and better-sqlite3.

Authentication

Write operations on /assets and every operation on /alerts (alerts contain a personal email address) require an API key. Send it as a request header: 

x-api-key: <your API key>

Requests missing the header, or sending the wrong key, receive a 401 response.

Assets

GET /assets

List assets. Public, no API key required.

  • limit (optional, integer, default 20) - page size
  • offset (optional, integer, default 0) - page start
  • name (optional, string) - filter by partial name match
  • symbol (optional, string) - filter by partial symbol match
  • sort (optional, e.g. current_price or -created_at) - sort by field, ascending by default, leading - for descending

Example: GET /assets?limit=10&offset=0&symbol=BT&sort=-current_price

GET /assets/:id

Get a single asset by id. Public, no API key required.

POST /assets

Create a new asset. Requires API key.

{
  "name": "Bitcoin",
  "symbol": "BTC",
  "category": "Layer 1",
  "current_price": 62000,
  "is_active": true
}

PUT /assets/:id

Update an asset. Requires API key. Any subset of the create fields may be sent. If current_price changes, every pending (not yet triggered) alert on this asset is re-evaluated as a side effect; alerts whose condition is now met are flipped to triggered. The response includes triggeredAlerts, the count of alerts newly triggered by this update. 

{
  "current_price": 65000
}

DELETE /assets/:id

Delete an asset. Requires API key. Deleting an asset also deletes its alerts (foreign key cascade).

Price Alerts

Every endpoint below requires the API key, including reads, since an alert's email field is personal data.

GET /alerts

List alerts. Requires API key.

  • limit (optional, integer, default 20)
  • offset (optional, integer, default 0)
  • email (optional, string) - filter by partial email match
  • asset_id (optional, integer) - filter by asset
  • direction (optional, "above" or "below")
  • is_triggered (optional, "true" or "false")
  • sort (optional, e.g. target_price or -created_at)

Example: GET /alerts?direction=above&is_triggered=false

GET /alerts/:id

Get a single alert by id. Requires API key.

POST /alerts

Create a new alert. Requires API key. asset_id must reference an existing asset. The target price must make logical sense relative to the asset's current price: for direction "above", target_price must be greater than the current price; for "below", it must be less. A target price within about 0.5% of the current price is also rejected as not meaningfully different. 

{
  "asset_id": 1,
  "email": "user@example.com",
  "direction": "above",
  "target_price": 70000
}

PUT /alerts/:id

Update an alert, e.g. change its target price. Requires API key. Re-runs the same validation as creation.

{
  "target_price": 72000
}

DELETE /alerts/:id

Delete an alert. Requires API key.

Response shape

Successful responses: { "success": true, "data": ... }, list endpoints also include a pagination object.

Error responses: { "success": false, "error": "..." } or, for validation failures, { "success": false, "errors": [ { "field": "...", "message": "..." } ] }.
